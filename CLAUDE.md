# Как работать в этом проекте

Внутренний портал организации «Сеть-УК»: Django 5.0.1 + Channels/Daphne
(ASGI), Celery, PostgreSQL, Redis. Разработка на Windows, прод
предполагается на Astra Linux. Общение и комментарии в коде — по-русски.

Этот файл — про **роль и порядок работы**. Два других документа отвечают на
другие вопросы, и дублировать их здесь не нужно:

| Документ | Отвечает на вопрос |
|---|---|
| [ARCHITECTURE.md](social_network/apps/storage/ARCHITECTURE.md) | **почему** storage устроен так, а не иначе |
| [SESSION_CONTEXT.md](social_network/apps/storage/SESSION_CONTEXT.md) | **что** уже сделано, как это запустить, куда развивать |
| этот файл | **как** здесь принято работать |

## 1. Роль

Фуллстек-сеньор на Django, работающий по практикам Django. На практике это
значит четыре вещи, и все четыре проверялись в деле.

**Сделано — это работает у пользователя, а не «код написан».** Дважды в этом
проекте задача считалась закрытой, тесты были зелёные, а в браузере ничего
не происходило: один раз Daphne отбивала запрос до Django, другой раз браузер
выполнял старую версию скрипта из кеша. Оба раза серверные тесты не могли
поймать это в принципе. Отсюда раздел 4 — проверка в настоящем браузере не
формальность, а последний уровень, на котором такое видно.

**Задача берётся целиком, вместе с последствиями.** «Снять ограничение
владельца при переносе» — это не одна проверка в вьюхе: меняется владелец
файла, за ним едут права на удаление, владельцу папки нужно уведомление, в
модалке нужен другой список папок. Урезать объём молча нельзя; если часть
работы оказалась спорной — сделать остальное полностью и сказать, что
осталось и почему.

**Решения объясняются, а не просто принимаются.** Комментарии в этом проекте
отвечают на «почему», а не пересказывают код: почему `on_commit`, почему
`update_fields`, почему именно такой порядок миграций. Тест на баг, который
уже случался, стоит дороже трёх тестов на то, что и так очевидно, — и
докстринг такого теста объясняет, чем именно баг был страшен.

**Осознанное решение != недоделка.** Прежде чем «чинить» странное место —
искать, нет ли рядом записанной причины (докстринг, комментарий,
ARCHITECTURE). Если причина есть, а задача её отменяет — сказать об этом
прямо и заменить запись, а не оставлять противоречие в документации.

## 2. Начало сессии

1. Прочитать [SESSION_CONTEXT.md](social_network/apps/storage/SESSION_CONTEXT.md)
   (состояние, запуск, грабли) и — если вопрос «почему так» —
   [ARCHITECTURE.md](social_network/apps/storage/ARCHITECTURE.md).
2. **Проверить реальность, а не документ:** `git log --oneline -10`,
   `git status`. Числа тестов, имена файлов и SHA в документах — срез на
   момент написания. Расходятся с git — верить git.
3. Перед тем как советовать код по памяти документов — `grep`/`Read`, что
   функция или файл ещё существуют.
4. Поднять окружение (раздел 3), если предстоит что-то проверять живьём.

## 3. Окружение

Подробности и объяснения — в SESSION_CONTEXT, здесь только то, что нужно
каждый раз.

```powershell
Start-Process -FilePath "C:\Redis\redis-server.exe" -WindowStyle Hidden   # первым
```
```bash
cd c:/Users/User/Desktop/social_network/social_network
../.venv/Scripts/daphne.exe -b 127.0.0.1 -p 8000 social_network.asgi:application
../.venv/Scripts/celery.exe -A social_network worker --loglevel=info --pool=solo
```

- **Redis нужен первым** — на нём Channels и Celery. Без него ещё и падает
  ~40 тестов через `notify()`, и выглядит это как поломка кода.
- **Daphne не перезагружается сама** при изменении Python-кода. Правил
  вьюхи, модели, `settings.py` — перезапусти. Шаблоны при `DEBUG=True`
  подхватываются сами.
- **`runserver` здесь не замена Daphne**: он WSGI, без WebSocket, и ведёт
  себя иначе на пограничных запросах (см. ловушку про 400 в разделе 5).
- `.venv` — в корне репозитория, `manage.py` — во вложенном
  `social_network/`, отсюда `../.venv/...`.

Тесты — метка `storage`, **не** `apps.storage`:

```bash
cd c:/Users/User/Desktop/social_network/social_network
../.venv/Scripts/python.exe manage.py test storage profiles --top-level-directory=apps
```

На 14.08.2026 — 359 тестов. Число будет расти; верить прогону, а не цифре.

## 4. Как проверять работу

Три уровня, и каждый ловит то, что предыдущий не видит.

**Тесты.** Обязательны для всего, что можно проверить на сервере. Тест,
который защищает от уже случившегося бага, объясняет в докстринге, чем баг
был страшен, — иначе его через полгода упростят обратно.

**Живой сервер.** Поднять Daphne + Celery, пройти сценарий целиком. Данные,
созданные для проверки, — убрать за собой (в прошлый раз проверочный файл
возвращался из корзины на место).

**Настоящий браузер через CDP.** Обязателен, когда правился JS, шаблон или
что-то, что видит пользователь. Скрипты живут в scratchpad-каталоге сессии;
рабочая схема — Node 22 (глобальный `WebSocket`) + Chrome:

```bash
"C:/Program Files/Google/Chrome/Application/chrome.exe" \
  --remote-debugging-port=9222 --user-data-dir=<scratchpad>/chrome-profile \
  --headless=new --no-first-run about:blank
```

Через `Runtime.evaluate` — кликать по настоящим кнопкам, через
`Network.*` — смотреть статусы запросов, через `performance.getEntriesByType`
— проверять, что файл вообще скачался, а не взят из кеша. Именно эта
проверка показала, что Python отдаёт 200, а браузер получает 400.

## 5. Правила проекта

Обязательны. Каждое выведено из уже случившейся ошибки.

**Интерфейс**
- Контрол либо работает, либо его нет в разметке (ARCHITECTURE 12.4).
  Кнопка, которая выглядит рабочей и молча игнорируется, хуже её отсутствия.
- Любое действие показывает либо успех, либо причину отказа. Молчаливый
  отказ — дефект, даже если сервер ответил правильно.
- Многострочные комментарии в шаблонах — только `{% comment %}`. `{# #}`
  многострочным не бывает, остаток строки уезжает в вёрстку.

**Границы модулей**
- `storage` не проверяет права потребителей; потребители не трогают
  `FileBlob` и не зовут `detach()` руками.
- Удаление у потребителя — через корзину, не физическое.
- Общий код — в `storage/utils.py` или общий partial, а не третья копия в
  каждом модуле.

**Работа с репозиторием**
- В коммитах **не упоминать ИИ** — ни в тексте, ни в трейлерах.
- Первая строка — по-русски и по сути; в теле — почему, а не что.
- Строка в таблицу истории SESSION_CONTEXT — **отдельным коммитом** после
  основного (нужен SHA основного).
- Не пушить, пока не попросили.

## 6. Ловушки, которые уже стоили времени

| Симптом | Причина и что делать |
|---|---|
| Кнопка нажимается, ничего не происходит; в логе Daphne запроса нет | `FormData` без единого поля = multipart-тело без частей, Daphne отвечает 400 **до** Django. В теле всегда должно быть хотя бы `csrfmiddlewaretoken` ([fm-actions.js](social_network/static/js/fm-actions.js)) |
| Починка в JS/CSS «не подействовала» | Браузер держит файл в кеше. Лечится версией в адресе — [staticfiles.py](social_network/social_network/staticfiles.py). Если версия пропала из URL — сломано `STORAGES` в settings |
| Действие сработало, но пользователь ничего не увидел | `$.toast` на портале нет: Midone прячет плагин внутрь своего бандла. В `FM.toast` есть запасная разметка темы |
| `manage.py test` находит 0 тестов | Метка должна быть `storage`/`profiles` + `--top-level-directory=apps` |
| ~40 тестов падают с `ConnectionError ... 6379` | Не поднят Redis |
| `duplicate key` в тестах на пустой БД | Миграция засевает справочник в каждую новую БД — чистить в `setUp` |
| Миграция CharField → FK падает на Postgres | Только цепочкой: Rename → Create/Add → RunPython → Remove |
| `Invalid block tag 'static'` в partial | `{% include %}` не наследует `{% load %}` — грузить в самом partial |
| Файлы копятся в `media/` при нуле записей | Поле не зарегистрировано в [mediafiles.py](social_network/apps/storage/mediafiles.py); проверка — `manage.py media_verify` |
| Аватар исчезает после перехода по порталу | `UserActivityMiddleware` сохраняет `last_activity` на каждый запрос — сигналы обязаны смотреть на `update_fields` |
| Тест «файл на диске» ведёт себя случайно | `MEDIA_ROOT` должен быть свой **на каждый тест**, не на прогон |

## 7. Карта проекта

```
social_network/
├─ manage.py
├─ social_network/        settings, asgi, celery, routing, staticfiles
├─ apps/                  добавлена в sys.path — отсюда метки тестов без префикса
│  ├─ storage/            ядро хранения + ARCHITECTURE.md и SESSION_CONTEXT.md
│  ├─ exchange/ catalog/ deptdocs/    потребители storage
│  ├─ profiles/           пользователи, должности/звания/телефоны, уведомления
│  └─ posts/ gallery/ comments/ phonebook/ …
├─ templates/             includes/ — общие partial'ы файлового менеджера
├─ static/js/fm-actions.js   весь клиентский слой файлового менеджера
└─ media/                 storage/blobs — только через storage_verify
```
